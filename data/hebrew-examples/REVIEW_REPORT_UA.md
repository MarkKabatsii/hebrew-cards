# Результат локального редакторського перегляду

Переглянуто пари в `review_examples.csv` та шаблони, з яких вони створені: 974 речення до 487 слів одного власника. Для кожної пари є рішення в `review_decisions.csv`. Це повторний ШІ-редакторський перегляд; незалежної перевірки носієм мови не було. Наголос в українській транскрипції — приблизна навчальна підказка, не фонетичний запис.

Усі 974 записи залишаються `draft` у файлі імпорту. Окремо відібрано 50 кандидатів до 25 слів: ID 1–10, 21–33, 458 і 462, по два приклади. Перевірено їхній зміст, граматику, нікуд, приблизну вимову й переклад; це базові вирази, займенники, молоток і викрутка. Їхній точний перелік — `approved_pairs.csv`, речення зі статусом approved — `word_examples_approved.json`. У frontend вони потраплять лише після відповідного статусу в БД; локальний JSON сайт не імпортує автоматично.

924 інші приклади залишено чернетками після первинного перегляду. Не всі невипущені рядки містять помилки, але просте повторення шаблону не є достатнім контекстним/фонетичним підтвердженням. Сумнівні професійні терміни, скорочення, наголоси loanwords та багатозначні слова потребують додаткового звіряння.

## Виправлення

14 записів змінено; повні старі й нові значення та причина збережені в `content_changes.json`:

- №5, обидва: наголос `Легі́траот` → `Легітрао́т`.
- №36, обидва: «Я не хочу хотіти більше» замінено природнішими реченнями про бажання досягти успіху/хотіти більшого. Поки draft.
- №101/2 і №102/2: конкретні прохання про ще одну годину й зачекати мить. Поки draft.
- №108/2 і №109/2: «хочу тата/маму» замінено реченнями про роботу тата й читання мами. Поки draft.
- №183/2: `Статуя потворний` → `Статуя потворна`. Поки draft.
- №192/2: прибрано розрив `Гаміс па́р` → `Гаміспа́р`. Поки draft.
- №458/2 і №462/2: інший предметний контекст — молоток на столі та викрутка в ящику для інструментів.
- №461/2 і №492/2: наголос слова «полиця» `гама́даф` → `гамада́ф`. Поки draft.

У нотатках до конкретних пар також позначено: №20 (гайка та її вимова), №135 (означеність слова «світ»), №262 (написання полюса), №278/302 (котушка/обмотка, завада/несправність), №303 (невідповідність нікуду полярності й транскрипції), №330 (наголос construct form ременя), №331/470 (підшипники), №333 (клема/затискач), №435 (реєстр/рецепт), №437/448 (лещата/напилок), №451/474 (гідравлічний), №452 (транскрипція кілець). Вихідні `words` не змінювалися.

Наведені в CONTENT_NOTES_UA.md сторінки Академії івриту для підшипника, лещат і напилка не вдалося прочитати через доступний вебінструмент. Тому їх не використано як підтвердження для схвалення цих термінів.

## Ручний порядок роботи з БД

Агент не виконував жодного SQL на production та не публікував сайт.

1. За потреби виконати `00_inspect_examples_schema.sql`: лише читання колонок, обмежень і RLS; звірити з описом у CODEX_TASK_UA.md.
2. Для відсутніх прикладів використати оновлений `02_import_examples_draft.sql`. Він звіряє ID, власника та he/tr/ua вихідних слів і не перезаписує жодної існуючої пари.
3. Якщо раніше імпортовано початкові чернетки, використати `04_apply_reviewed_corrections.sql`. Це guarded UPDATE тільки 14 змінених пар: оновлює лише старі точні значення зі статусом draft. Уже виправлені значення пропускає; сторонні зміни або схвалені старі значення зупиняють транзакцію для звіряння.
4. Після перегляду вибраного контенту використати `05_approve_reviewed_pairs.sql`. Він працює лише з явними 50 парами та звіряє всі три тексти й вихідне слово. Відсутня/змінена пара зупиняє транзакцію. Уже схвалені однакові пари пропускаються. Це не глобальне схвалення.
5. `03_check_coverage.sql` перевіряє покриття. Якщо збігаються два вже схвалені речення №1 і інших змін немає, нових схвалень буде 48, підсумок — 50 approved та 924 draft. Якщо приклади №1 відрізняються, guarded approval зупиниться: звірити їх окремо, не перезаписувати автоматично.

Прямий CSV-імпорт `word_examples_approved.json` не замінює guarded SQL і не рекомендується для повтору.

## Артефакти та відтворюваність

Відредаговані: `word_examples_draft.csv`, `word_examples_draft.json`, `review_examples.csv`, `02_import_examples_draft.sql`.

Нові: `review_decisions.csv`, `content_changes.json`, `approved_pairs.csv`, `word_examples_approved.json`, `00_inspect_examples_schema.sql`, `04_apply_reviewed_corrections.sql`, `05_approve_reviewed_pairs.sql`, `sync_reviewed_examples.py`, `validate_reviewed_examples.py`, цей звіт.

`sync_reviewed_examples.py` читає вже відредагований CSV, рішення й журнал змін; синхронізує JSON та SQL без генерації речень. `build_examples.py` збережений як початковий генератор і не запускався; його повторний запуск затре редакторські зміни. Архів `data/hebrew_examples_for_codex.zip` залишився початковим і не є оновленим набором.

Обидва Python-валідатори пройшли. CSV/JSON/паралельний перегляд і SQL staging values узгоджені для всіх 974 записів, 14 виправлень і 50 кандидатів. Це структурна перевірка артефактів, а не виконання SQL чи підтвердження всієї мовної якості. Frontend перевірки описані в [tests/EXAMPLES_UA.md](../../tests/EXAMPLES_UA.md).
