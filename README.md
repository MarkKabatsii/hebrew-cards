# hebrew-cards

Картки для вивчення івриту: слово, транскрипція, переклад. Frontend: HTML/CSS/JS. База даних і вхід: Supabase. Хостинг: Netlify.

[Відкрити сайт](https://learnhebrewapp.netlify.app/pages/login.html)

## Структура

```text
index.html          екран карток (головна)
pages/              решта сторінок: quiz, decks, add, import, login
css/                base (спільне), cards, forms, decks
js/                 config (ключі), taxonomy (категорії), store (база), ui (меню, фільтри),
                    parser (розбір імпорту) і по одному файлу на сторінку
sql/                schema.sql (нова база), migrate_v2.sql–migrate_v4.sql (оновлення існуючої)
data/               приклади файлів для імпорту
```

Міграції запускайте за порядком і по одному разу; `schema.sql` призначений для нової бази.
`migrate_v4.sql` додає захист від дублікатів, порожніх текстів і від’ємного прогресу.
Він не видаляє картки. Для перевірки стану бази використовуйте
`sql/diagnostics/01_inspect_words.sql` у Supabase SQL Editor.

## Додавання та імпорт слів

Ручне додавання й імпорт використовують спільну перевірку обов’язкових полів,
івритських літер, категорій і розділів. Нікуд зберігається; літери інших абеток
у полі івриту відхиляються. Правильність транскрипції та перекладу потрібно
перевіряти окремо.

Імпорт підтримує JSON-масив, CSV, TSV і текстові списки з роздільником `;` або `|`.
CSV може містити заголовки й поля в подвійних лапках. Кнопка «Перевірити»
нічого не записує; помилки в списку блокують імпорт до їх виправлення.

Перед кожною спробою застосунок перечитує БД і пропускає дублікати.
Запис виконується блоками по 200 карток: після збою попередні блоки можуть
залишитися в БД. Текст зберігається для повтору, який пропустить уже додані слова.
Файли в `data/` — приклади для імпорту; їх оновлення не змінює наявні картки в БД.

## Приклади вживання

Схвалені речення з `word_examples` показуються на звороті навчальних карток.
Другий приклад розгортається через «Ще один приклад». Чернетки не показуються;
помилка завантаження прикладів не блокує повторення слів.
Підготовка контенту та ручний порядок імпорту описані в
[data/hebrew-examples/REVIEW_REPORT_UA.md](data/hebrew-examples/REVIEW_REPORT_UA.md).

## Перевірки

Регресійні перевірки збереження прогресу, валідації та імпорту (потрібен Node.js):

```bash
node --test tests/progress.test.cjs tests/import.test.cjs tests/examples.test.cjs
```

Тести використовують підставні відповіді сервера й не змінюють живу БД.
Сценарії ручної перевірки описані в [tests/README_UA.md](tests/README_UA.md)
та [tests/IMPORT_UA.md](tests/IMPORT_UA.md).
Перевірки прикладів і локальний браузерний тест описані в
[tests/EXAMPLES_UA.md](tests/EXAMPLES_UA.md).
